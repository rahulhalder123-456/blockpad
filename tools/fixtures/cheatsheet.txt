URL encoding

Web challenges often encode special characters in URLs. For example:

    %7B → {

    %7D → }

    %20 → space

Decode a URL-encoded flag with:
bash

python3 -c 'import urllib.parse; print(urllib.parse.unquote("pwn.college%7Bexample%7D"))'

Output:
text

pwn.college{example}

Important: URL encoding is not encryption. It is a representation of characters for safe transport.

3. Redirects

A redirect response typically includes a Location header telling the client where to go next.

For example, the initial request might return:
http

HTTP/1.1 302 FOUND
Location: /aBxPmzjf-access

The target URL is /aBxPmzjf-access.
bash

# Inspect the redirect
curl -i http://challenge.localhost/

Without -L, curl generally displays the redirect response instead of requesting the destination.
JavaScript redirects

A page can redirect the browser with:
javascript

location = "http://challenge.localhost/attempt";

Or after an asynchronous operation:
javascript

fetch("/endpoint")
  .then(r => r.text())
  .then(data => {
    location = "/next";
  });

Use the first form for a direct redirect.
4. Cookies and session state

Cookies allow a server to associate requests with state maintained across multiple requests.
curl cookie workflow
bash

# Receive and save cookies
curl -c cookies.txt http://challenge.localhost/

# Send saved cookies on the next request
curl -b cookies.txt http://challenge.localhost/

    -c specifies the cookie jar to write received cookies to.

    -b specifies cookies to send from a cookie jar or explicit cookie string.

Common mistake: If the first request sets a cookie and the next request requires it, don't delete the cookie jar between requests.
Python requests: sessions
python

import requests

s = requests.Session()

r1 = s.get("http://challenge.localhost/")
r2 = s.get("http://challenge.localhost/")

print(r2.text)

A Session persists cookies between requests automatically. This is generally simpler than manually copying cookie values into headers.
5. HTTP requests with Python

The requests library is useful when a challenge requires multiple requests, redirects, cookies, or parameters.
python

import requests

url = "http://challenge.localhost/"
r = requests.get(url)

print(r.status_code)
print(r.headers)
print(r.text)

Custom headers
python

headers = {"Host": "challenge.localhost"}

r = requests.get(
    "http://127.0.0.1/",
    headers=headers
)

print(r.text)

The Host header tells the server which hostname the request targets. This matters when multiple virtual hosts share an IP address.
GET parameters
python

params = {
    "secure_key": "example",
    "token": "12345"
}

r = requests.get(
    "http://challenge.localhost/evaluate",
    params=params
)

print(r.url)
print(r.text)

Using params= avoids manually assembling and URL-encoding the query string.

11. Final challenge-solving checklist

When you open a new Talking Web challenge, follow this sequence:

    Read the server code. Identify the route, required method, query parameters, form fields, cookies, and headers.

    Understand the response. Determine whether the endpoint returns HTML, plain text, JavaScript, a redirect, or a cookie.

The main lesson

Most of these challenges test one HTTP concept at a time. Learn to recognize whether the missing piece is a path, redirect, header, cookie, GET parameter, POST field, or JavaScript execution context. Once you identify it, the solution is usually short.
